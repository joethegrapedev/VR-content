# How the app works

Written for someone who needs to run training sessions or explain the app, not
necessarily to modify it. The last section is for developers.

---

## The training session

### Starting up

The app opens in the **Menu** scene, a 3D room the trainee is standing in. From here
they can start a session, open the **Tutorial**, view the **Leaderboard**, or adjust
**Audio Settings**.

Before a session begins the trainee enters their name on an in-headset keyboard
(the **Keyboard** scene). The name is what appears on the leaderboard afterwards, so it
matters that they type something recognisable.

They also choose a session length:

| Length | Used for | Results file |
|---|---|---|
| **3 minutes** | Short demonstrations and visitors | `RSAF_VIP_Leaderboard.xls` |
| **10 minutes** | Normal training | `RSAF_Leaderboard.xls` |

The two lengths write to **separate leaderboards**, so a demo run never pollutes the
real training results.

### In the warehouse

The trainee is placed in the warehouse (the **5SD Map** scene) and moves around it
physically and by teleporting. A timer and a running score are displayed.

**Thirteen safety hazards** are placed around the warehouse. Approaching one opens a
multiple-choice panel asking what the correct response is.

### Scoring

- Each hazard is worth **40 points**.
- Every wrong answer on that hazard costs **10 points**, and the panel stays open until
  the right one is chosen.
- So a hazard answered correctly first time scores 40; after one mistake, 30; and so on.
- Choosing correctly marks that hazard complete and adds to the task count.

A hazard is highlighted **green** when handled correctly and **yellow** once a wrong
answer has been given on it.

### Ending

A session ends in one of two ways:

- **All thirteen hazards handled** — the run counts as finished.
- **The timer runs out** — the run is recorded as **DNF** ("did not finish"), keeping
  whatever score was reached.

Either way the trainee is returned to the classroom area and the result is written to
the leaderboard spreadsheet.

## Where the results go

Results are stored **on the headset**, not on any computer or server. Nothing is
uploaded anywhere and the app needs no internet connection.

The file lives at:

```
/storage/emulated/0/Android/data/com.sp.fyp3a25.rsafvrwarehouse/files/Output/
```

Use `install/get-results-mac.command` or `install/get-results-windows.bat` to copy it
to a computer — see [INSTALL.md](../INSTALL.md#collecting-trainee-results).

### What the columns mean

| Column | Meaning |
|---|---|
| **Date** | The date the run was completed |
| **Name** | What the trainee typed on the keyboard screen |
| **Points** | Final score — 40 per hazard, less 10 per wrong answer |
| **Timing** | Time taken, as `MM:SS`, or **DNF** if the timer expired |
| **Tasks** | Hazards handled, out of 13 |

The sheet is a **ranked leaderboard**, not a raw log: entries are inserted in score
order and lower scores are pushed off the bottom as better ones arrive. It is a
high-score table, so do not treat it as a complete attendance record.

### Two things worth knowing

- **Results are per headset.** Collect from each headset used in a session.
- **Uninstalling the app deletes them.** Always collect before removing or updating it.

## Sound

The original app had narration and a few one-shot effects, but no music, no room
atmosphere and no footsteps, which made it feel static. Music, ambience, footsteps,
impact sounds and UI feedback were added, and are mixed on four independent channels:

| Channel | What it carries |
|---|---|
| **Dialogue** | Narration and spoken instructions |
| **Sound Effects** | Interactions, impacts, footsteps, UI |
| **Music** | Background music per screen |
| **Ambience** | Warehouse room tone, machinery, air handling |

Each has its own slider in the app's Audio Settings screen, and the setting persists
between sessions on that headset. A silent app is nearly always a slider left at zero
by a previous user.

Every music and effect file is **generated by code** rather than licensed, so there are
no attribution or licensing obligations. See [AUDIO.md](AUDIO.md) for the full detail.

## Notes for developers

### Origin

No original Unity project survived. This one was reconstructed from the compiled
Windows build by extracting assets and decompiling the game assembly. See
[REBUILD_BRIEF.md](REBUILD_BRIEF.md) and [../STATUS.md](../STATUS.md).

### Storage paths

`SavePaths` is the single source of truth for on-disk locations. All writes go to
`Application.persistentDataPath`:

| What | Path under `persistentDataPath` |
|---|---|
| Leaderboards | `Output/` |
| Player name | `_MyProject/saves/PlayerInfo.json` |
| Audio settings | `_MyProject/saves/AudioSettings.json` |

The original build wrote to `Application.dataPath`, which is writable on Windows but
resolves **inside the read-only APK on Android**. Every write threw, and because the
throw happened before the scene load, the app could never reach the warehouse at all.
That was the single defect that made the Quest build unusable, and it is worth knowing
about before adding any new file writes.

### Session flow in code

```
Menu ──▶ Keyboard ──(name saved)──▶ 5SD Map ──(UpdateExcel)──▶ classroom
```

`MyRuntimeTest` owns the timer, the task count and the end-of-run write.
`MyRuntimeTest.UpdateExcel()` is the **single funnel** for both completion and DNF —
anything that should happen at the end of a run belongs there, not in a caller.

`TaskStatus` holds thirteen booleans, one per hazard. `OptionBox` handles the
multiple-choice panels and the 40-point / −10-point scoring.

### Rebuilding

See [BUILDING.md](BUILDING.md). Note that a plain `git clone` is **not** sufficient —
the recovered art assets are not in the repository.
